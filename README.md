# Витрина уценённых товаров

Flask-приложение: каталог с категориями, карточки товаров (до 10 фото, видео-ссылка,
дефект, габариты), корзина, оформление заказа с уведомлением в Telegram, админка `/adm`,
статистика посещений/конверсии, бэкап и импорт данных (совместим со старой структурой
`backup/`), выгрузка бэкапа в S3 Timeweb Cloud (папка `BU_TOVAR`).

## Локальный запуск

```bash
cp .env.example .env      # заполнить значения
pip install -r requirements.txt
python app.py             # http://localhost:8000
```

Админка: `http://localhost:8000/adm` — пароль по умолчанию задаётся переменной
`ADMIN_PASSWORD` (изначально `sp010203`), при первом старте хешируется и сохраняется в БД.
**Смените пароль сразу после первого входа** (Настройки → Новый пароль администратора).

## Деплой на Timeweb Cloud (App Platform, Docker)

1. Запушьте репозиторий в GitHub/GitLab.
2. В Timeweb Cloud создайте приложение типа **App Platform → Docker**, укажите репозиторий,
   Dockerfile лежит в корне.
3. Подключите **постоянный диск (volume)** на `/data` — там хранится SQLite-база и все
   загруженные фото. Без volume данные пропадут при пересборке контейнера.
4. Задайте переменные окружения (см. `.env.example`):
   - `SECRET_KEY` — случайная строка
   - `ADMIN_PASSWORD` — первоначальный пароль (потом смените в админке)
   - `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` — обязательно только через переменные окружения
     Timeweb Cloud (в админке эти поля не редактируются — так безопаснее). После изменения
     значений нужно перезапустить контейнер
   - `TELEGRAM_PROXY_URL` — прокси для Telegram API можно задать так же через переменную,
     либо позже поменять из админки без пересборки контейнера (админка имеет приоритет,
     если задана)
   - `S3_ENDPOINT_URL`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_BUCKET`, `S3_REGION` —
     доступы к S3 Timeweb Cloud для бэкапов
   - `S3_BACKUP_FOLDER=BU_TOVAR` — бэкапы кладутся именно в эту папку бакета
5. Порт контейнера — `8000` (уже прописан в Dockerfile и читается из `PORT`).
6. Домен/HTTPS настраиваются в панели Timeweb Cloud App Platform.

Все секреты (пароли, токены, ключи S3) передаются только через переменные окружения
и нигде не хранятся в коде.

## Обновление уже развёрнутого сайта

При каждом запуске (`db.init_db()`) приложение автоматически проверяет схему базы данных
на диске `/data` и добавляет недостающие колонки (например `is_top` у товаров,
`processed` у заказов), не трогая существующие данные. Просто перевыложите новый образ —
пересоздавать базу или переносить бэкап заново не нужно.

## Перенос данных со старого сайта

1. На старом сайте выполните `python3 create_backup.py` — создастся папка
   `backup_ГГГГ-ММ-ДД/`.
2. Переименуйте её в `backup/` и положите в корень **нового** проекта до первого запуска
   контейнера (например, смонтируйте как часть образа или скопируйте на volume `/app/backup`
   рядом с `app.py`).
3. При первом старте `startup_import.py` автоматически найдёт `backup/`, импортирует
   товары, категории, фото и настройки, сохранив исходные ID, и создаст файл
   `backup/.imported`, чтобы повторный импорт не выполнялся.
4. Импорт также доступен вручную из админки: **Бэкапы → Импорт бэкапа** — можно загрузить
   тот же zip-архив в любой момент (например, на другую копию сайта).

## Резервное копирование в дальнейшем

В админке (**Бэкапы**) доступно:
- скачать полный бэкап (`store.db`, `products.csv`, `categories.csv`, `settings.json`,
  все фото) одним zip-архивом;
- выгрузить этот же архив прямо в S3 Timeweb Cloud, в папку `BU_TOVAR`;
- посмотреть список уже выгруженных в S3 архивов.

## Структура проекта

```
app.py              Flask-приложение и все маршруты
config.py            Конфигурация из переменных окружения
db.py                 SQLite-схема и доступ к БД
backup.py            Создание/импорт бэкапов, работа с S3
telegram.py          Отправка уведомлений о заказах (с поддержкой прокси)
create_backup.py     Скрипт для создания бэкапа на текущем/старом сайте
startup_import.py    Автоимпорт backup/ при первом запуске
templates/           Публичные страницы + templates/admin/ — админка
static/               CSS, JS, а также static/uploads не используется —
                      реальные файлы хранятся в /data (см. config.py)
```
